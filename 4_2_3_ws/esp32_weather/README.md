# ESP32 метеостанція (ESP-IDF 6.x)

ESP32 DevKit + OLED 0.96" (SSD1306 128x64, I2C) + BMP280/BME280 + годинник DS1307 (Tiny RTC) +
GPS GP-01 + датчик руху AM312.

- Екрани по колу: **час** (+ день тижня і дата, 12 с) → температура → вологість (лише BME280) →
  тиск (hPa і мм рт. ст.) → місто з координатами → прогноз на 3 дні. Екрани без даних пропускаються.
- Час: **GPS → NTP → DS1307 → час збірки**. DS1307 дає час одразу після старту і після сну,
  без WiFi і без очікування GPS. GPS і NTP підводять DS1307 (не частіше разу на годину).
  В RTC зберігається UTC, на екрані київський час з літнім/зимовим.
- Індикатори на екрані часу: ліворуч WiFi (`W` є IP, `w` підключається, `X` SSID не задано)
  і GPS (`G` є фікс, `g` пошук), праворуч RTC (`R` ок, `!` проблема).
- Прогноз (Open-Meteo) і назва міста (BigDataCloud) тягнуться за координатами з GPS по WiFi,
  оновлюються раз на 30 хв.
- **Сон:** якщо PIR не бачить руху `CONFIG_WS_INACTIVITY_S` секунд (300), станція вимикає OLED, GPS
  і WiFi та засинає (deep sleep). Рух будить її. Місто і прогноз зберігаються в RTC-пам'яті.
- Раз на секунду дані йдуть по UART2 на ESP32-S3 (формат нижче).
- Тип датчика визначається автоматично: BMP280 (0x56..0x58) або BME280 (0x60).
  **BMP280 не має датчика вологості** - з ним екран вологості пропускається.

## Підключення (ESP32 DevKit)

| Що | GPIO ESP32 |
|---|---|
| OLED / BMP280 / DS1307: SDA | 21 |
| OLED / BMP280 / DS1307: SCL | 22 |
| VCC OLED і BMP280 | 3V3 |
| RTC (Tiny RTC) VCC | **5V (VIN)**, див. нижче |
| UART2 TX → RX на ESP32-S3 | 17 |
| UART2 RX (резерв) | 16 |
| GPS GP-01 TX → ESP32 RX (UART1) | 25 |
| GPS GP-01 RX ← ESP32 TX | 26 |
| GPS VCC | 3V3 (або через MOSFET з GPIO, `CONFIG_WS_GPS_EN`) |
| PIR AM312 OUT | 33 (RTC-пін, будить із сну) |
| PIR AM312 «+» / «−» | 3V3 / GND |
| GND | GND (спільна з ESP32-S3) |

## Модуль Tiny RTC (DS1307)

- DS1307 потребує **5 В**. На 3.3 В він переходить на батарейку і по I2C не відповідає.
  У сні модуль має лишатися під напругою (VIN), інакше час піде на батарейку.
- Підтяжки SDA/SCL на модулі йдуть до його VCC. При живленні 5 В вони піднімають лінії до 5 В,
  а GPIO ESP32 розраховані на 3.3 В. Зніми дві підтяжки SDA/SCL з модуля RTC (на OLED/BMP-модулях
  свої підтяжки до 3.3 В лишаються). Знайти їх: мультиметром між SDA і VCC має бути ~4.7 кОм.
- Якщо батарейка не перезаряджається (CR2032), вимкни ланцюжок заряджання (діод D1 / резистор поруч)
  або став LIR2032.
- Шина I2C працює на 400 кГц (OLED, BMP), а DS1307 драйвер обмежує до 100 кГц.
- Адреси на шині: OLED 0x3C, BMP/BME 0x76, DS1307 0x68, EEPROM 24C32 0x50 - конфліктів немає.
  На старті в логах друкується список знайдених пристроїв.

## Якщо WiFi не підключається

Дивись `idf.py monitor`: у логу є `reason=...` з поясненням.

| reason | причина |
|---|---|
| `SSID is not set` / `X` на екрані | не заданий SSID у menuconfig (за замовчуванням `YOUR_WIFI_SSID`) |
| NO_AP_FOUND | помилка в назві, мережа лише 5 ГГц (ESP32 не вміє), далеко від роутера |
| AUTH_FAIL / HANDSHAKE_TIMEOUT | невірний пароль, або роутер лише WPA3 |
| ASSOC_FAIL | MAC-фільтр, ліміт клієнтів |
| BEACON_TIMEOUT | слабкий сигнал |

Також: перезавантаження під час підключення = слабке живлення USB (WiFi дає піки струму), заміни кабель.
Без WiFi годинник працює далі від GPS/RTC, але прогноз і місто не оновлюються.

## Збірка (ESP-IDF 6.x)

```bash
idf.py set-target esp32
idf.py menuconfig        # Weather station -> WiFi SSID/пароль, піни, адреси
idf.py build flash monitor
```

Якщо збірка не влазить у розділ 1 МБ: Partition Table → «Single factory app (large), no OTA».
`sdkconfig` містить пароль WiFi відкритим текстом - не публікуй його і не додавай у git
(`.gitignore` це вже виключає).

## Формат UART

```
$SENS,<temp C>,<hum %|NA>,<press hPa>*<XOR hex>\r\n
```

Контрольна сума - XOR усіх байтів між `$` і `*`. 115200 8N1.
Приклад: `$SENS,23.45,NA,1013.25*2C`

Якщо в menuconfig увімкнути `WS_UART_EXTRA`, раз на хвилину додатково йдуть рядки
`$GEO,<lat>,<lon>,<CITY>*XX` і `$FCST,<0..2>,<YYYY-MM-DD>,<tmin>,<tmax>,<WMO code>*XX`.
За замовчуванням вимкнено, щоб не збивати парсер на ESP32-S3.

## Структура

- `main/main.c` - ініціалізація, завдання, супервізор сну
- `main/ui.c` - цикл екранів
- `main/ssd1306.c/.h` - драйвер дисплея + шрифт 5x7
- `main/bmp280.c/.h` - драйвер BMP280/BME280
- `main/ds1307.c/.h` - драйвер годинника DS1307
- `main/clock_sync.c/.h` - вибір джерела часу, запис в DS1307
- `main/wifi_time.c/.h` - WiFi + SNTP (діагностика причин відключення)
- `main/gps.c/.h` - NMEA з GP-01 (час, дата, координати)
- `main/weather.c/.h` - прогноз і назва міста
- `main/motion.c/.h`, `main/power.c/.h` - PIR і deep sleep
- `main/uart_out.c/.h` - зв'язок з ESP32-S3
- `main/i2c_bus.c/.h`, `main/timeutil.c/.h` - допоміжне
- `main/Kconfig.projbuild` - налаштування в menuconfig
